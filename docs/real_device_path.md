# 真机完整验收路径研究

本文档记录 Windows 版在通过「真机负向验收」之后，走向「完整定位验收」所需的研究结论、合规边界与待办事项。

## 1. 协议兼容性对照结论（TetherPin v1.0.0 vs 本实现）

- TetherPin 发布版 **v1.0.0**（tag，提交 `b918be4`，2026-11-19）与最新 main（提交 `791b308`，2026-11-22）之间的**协议核心逐字节一致**（SHA-256 相同），最新 main 仅新增 `README.en.md` 与语言切换，未改协议。
- 本项目的 `core/wire.py` 与 v1.0.0 的 `wire.py` 逻辑一致（仅补充类型注解与文档字符串），关键常量一致：
  - 链路标志：`SYN/ACK/EAK/RST = 0x80/0x40/0x20/0x10`
  - 探测帧：`DETECT = ff550200ee10`
  - 控制消息头：`@@` + `>2sHH`
- 认证助手 JSONL 契约（`{"op":"certificate"}` / `{"op":"sign","challenge":...}`）与 TetherPin `tools/local_mfi_v3_helper.py` 一致，未绕过认证。
- 真机负向验收已实际走通：握手 → 身份识别（`0x1d00/0x1d02`）→ 设备发起认证（`0xaa00`）。

**结论：协议与认证行为层面无已知兼容性差异，无需为消除报错而修改核心逻辑。**

## 2. 合法认证材料获取途径

本项目遵循合规红线：**不内置、不分发任何 MFi 证书或私钥**，认证材料由使用者外部配置（GUI「认证材料」区，对应环境变量 `OUYE_LOCATION_STUDIO_CERT_FILE` / `OUYE_LOCATION_STUDIO_KEY_FILE`）。

| 途径 | 说明 | 授权状态 | 本项目态度 |
| --- | --- | --- | --- |
| **A. 合法 MFi 配件身份（首选）** | 通过 Apple MFi 授权计划或与已获授权的配件厂商合作，取得合法 accessory identity（`certificate.p7b` + 匹配的 P-256 `identity.pk8`） | 合法授权 | **推荐**，唯一无授权争议、可合法分发的途径 |
| B. DiPlay 公开材料 | TetherPin 文档提及的「从公开 Carlinkit 固件恢复的共享配件证书/私钥」，含于 DiPlay preview APK | DiPlay 声明「不作为源代码重新许可」「持续接受与一般分发适用性未解决」 | **不集成、不复制、不加入发布包** |

> 途径 B 属于「授权状态未解决」的材料。按本项目红线（不得提取第三方 EXE/APK 内置私钥、不得复制没有授权的认证材料），本项目**不提供、不集成** DiPlay 导入器，也不分发任何从第三方提取的身份文件。使用者若自行评估并选择该途径，属其个人决策，与本项目无关。

## 3. 合规红线复核（均满足）

1. 不内置/不分发 MFi 证书与私钥——`auth_helper.py` 仅实现 JSONL 契约，从调用方配置的文件读取身份，不做任何内置。
2. 不伪造定位成功——`phone_location_verified` 恒为 `False`；链路 ACK 明确标注「不代表手机已定位成功」。
3. 不提取第三方 EXE/APK 内置私钥、不复制无授权材料、不将其加入发布包。
4. 不采集/不输出序列号、UDID、Apple ID、健康数据、真实位置。

为在获得合法认证材料后做交叉验证，可下载**原版 TetherPin v1.0.0** 与本项目分别连接同一台真机，对比认证与订阅行为。

- 下载地址：https://github.com/xmz28/tetherpin-ios/releases/tag/v1.0.0
- 官方校验值（`SHA256SUMS.txt`）：
  - `TetherPin.exe` → `43c682ef43389caea6bbc62dc2543489c87f66ec3a9d6e460e5ff1d24a220003`

> 本方案仅作**独立对照**，不替代本项目自身的验收，也不以「原版能跑」作为本项目通过验收的依据。

## 5. 完整定位验收待办（需真机 + 合法认证材料）

在用户提供合法认证材料后，按顺序执行：

1. 配置合法 `certificate.p7b` + `identity.pk8`。
2. 完整会话：认证（`0xaa00/0xaa02/0xaa05`）→ 订阅（`0xfffa`）→ 坐标发送（GGA/RMC）→ 停止（`0xfffc`）。
3. 手机地图确认目标位置已生效（由用户本人确认，工具不代判定）。
4. 停止后确认位置已恢复真实定位（`RestoreConfirmDialog`）。
5. 记录事件序列、发送计数、`phone_location_verified=False` 语义是否在 UI 如实呈现。
