# 协议参考 / Protocol reference

本文描述本客户端实现的 iAP2 子集，并非完整规范。研究来源见 [sources.md](sources.md)。

## 传输与帧结构

USB 通过已信任的 lockdown 连接（`pymobiledevice3`，显式选择 USB）打开
`com.apple.carkit.service`。USB 直接以 SYN 协商开始，无需蓝牙检测序列。

| 偏移 | 链路包字段 |
| --- | --- |
| 0–1 | 标记 `FF 5A` |
| 2–3 | 总长，大端 |
| 4 | 标志：SYN `80`、ACK `40`、EAK `20`、RST `10` |
| 5 | 序列号，模 256 |
| 6 | 累计确认号 |
| 7 | 会话标识 |
| 8 | 头校验和（前 9 字节求和模 256 为 0） |
| 9+ | 可选负载 + 其校验和 |

空包为 9 字节。SYN 携带 10 字节链路参数块与 `(id, type, version)` 会话三元组。客户端声明
控制会话 `(1, 0, 2)`，接收上限 4096 字节。

链路同时只保留一个待确认出站包，在有限次数内重传，确认收到的包并去重。选择性重传窗口与
文件传输会话未实现。

## 控制消息

消息含标记 `40 40`、大端 16 位总长、16 位标识与参数。每个参数含 16 位长度（含 4 字节头）、
16 位标识与数据。文本为 UTF-8，以 NUL 结尾。嵌套组使用相同的参数编码。

| 标识 | 方向 | 含义 |
| --- | --- | --- |
| `1D00` | 手机 → 配件 | 开始身份识别 |
| `1D01` | 配件 → 手机 | 身份与能力 |
| `1D02` / `1D03` | 手机 → 配件 | 身份识别接受 / 拒绝 |
| `AA00` | 手机 → 配件 | 请求证书 |
| `AA01` | 配件 → 手机 | 证书响应 |
| `AA02` | 手机 → 配件 | 挑战 |
| `AA03` | 配件 → 手机 | 签名响应 |
| `AA04` / `AA05` | 手机 → 配件 | 认证失败 / 成功 |
| `FFFA` | 手机 → 配件 | 开始定位信息 |
| `FFFB` | 配件 → 手机 | 定位信息 |
| `FFFC` | 手机 → 配件 | 停止定位信息 |

身份包含字段 0–9、语言 12/13、USB 传输组 16、定位组 22。定位组声明组件 ID 0、名称 1、
能力 17/18（GGA/RMC）。不声明无线 CarPlay。

定位订阅以空参数 1（GGA）与空参数 2（RMC）选择；可选参数 `8001` / `8002` 以 32 位毫秒指定
最小间隔。发送方遵循这些间隔与自身间隔，最小 1 秒。

每条 NMEA 语句占据 `FFFB` 中独立的参数 0，带 CRLF 与 NUL 结尾。校验和异或 `$` 与 `*` 之间的
字符。客户端发送静止的 GGA/RMC 定位，UTC 时间在发送时生成。`FFFC` 立即清空活动订阅。

## 认证边界

客户端将证书提交与挑战签名委托给本地 JSON-lines 子进程，见
[authentication.md](authentication.md)。任何凭证材料都不属于本包。
